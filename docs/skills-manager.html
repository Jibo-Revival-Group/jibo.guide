Skills Service Manager

The Skills Service Manager (SSM) is the Node.js process that runs inside Jibo's Electron shell and handles everything to do with skills: launching them, terminating them, switching between them, and routing voice commands to the right one. It exposes a browser UI and an HTTP API on port 8779 that you can use to manage skills from any device on the same network.

The Browser UI

Open a browser and navigate to:

http://<jibo-ip>:8779

You'll see a list of every skill installed on Jibo with buttons to Launch, Stop, and open the skill's Chrome DevTools debugger.

ℹ️ Port 8779 availability

Port 8779 is open in all modes that include the SSM — including int-developer, developer, and normal (via the JiboOS firewall patch). If the page doesn't load, check that Jibo has finished booting and the SSM is running.

What Is a Skill?

Everything Jibo does is a skill — his eye, his menu, his clock, his idle animations. Skills are Node.js packages installed on the robot under:

PathContents
/opt/jibo/Jibo/Skills/@be/be/ The @be/be host and, on current BEam images, its bundled packs under skills/.
/opt/jibo/Skills/ Third-party and developer-installed skills

The most important skill is @be/be — the Be host skill. It's Jibo's main process: his eye, his animated face, his main menu, and the container that hosts all other skills. If something goes wrong with Jibo's behaviour, restarting Be is the first thing to try.

ℹ️ BEam skill layout

Current BEam releases put system packs under /opt/jibo/Jibo/Skills/@be/be/skills/ and have the system manager list @be/be as the launchable host. Older stock/community images may use a different layout, so inspect /opt/jibo/Jibo/Skills/ before copying a package or changing a path.

Restarting the Be Skill (Soft Reboot)

Restarting @be/be via the SSM brings Jibo back to his eye screen and re-initialises all sub-skills without rebooting the whole robot. It's much faster than a full reboot and is the standard way to apply skill changes.

In the browser UI at :8779, find @be/be, click Stop, then Launch.

Or via curl from your computer:

# 1. Stop Be
$ curl -s -X POST http://<jibo-ip>:8779/terminate \
  -H "Content-Type: application/json" \
  -d '{"command": "@be/be"}'

# 2. Launch Be
$ curl -s -X POST http://<jibo-ip>:8779/launch-dev \
  -H "Content-Type: application/json" \
  -d '{"command": "@be/be"}'

HTTP API Reference

All endpoints are on http://<jibo-ip>:8779.

MethodEndpointDescription
GET /skill/list Returns a JSON list of all installed skills and their running state
POST /launch-dev Launch a skill. Body: {"command": "skill-name"}
POST /terminate Stop a skill. Body: {"command": "skill-name"}
GET /version Returns the SSM version string
GET /devtools Chrome DevTools target list for the currently running skill (port 9191)
GET /ssm-devtools Chrome DevTools target list for the SSM itself (port 12345)

List installed skills

$ curl -s http://<jibo-ip>:8779/skill/list | python3 -m json.tool

Debugging Skills

The SSM exposes Chrome DevTools for both the currently running skill and the SSM process itself. Open these in a Chromium-based browser.

WhatURL
Skill debug logs (currently running skill) http://<jibo-ip>:9191
SSM debug logs http://<jibo-ip>:12345
ℹ️ Opening the DevTools inspector

In Chrome or Edge, go to chrome://inspect, click Configure…, and add <jibo-ip>:9191 and <jibo-ip>:12345. The skill and SSM processes will appear under "Remote Target" and you can open a full DevTools panel for each.

8585 System Manager Platform-level service control (start/stop platform services, wifi, mode, etc.)

How the SSM Fits In

When Jibo boots, the system manager starts the SSM as a managed service. The SSM in turn:

  • Reads all installed skills from /opt/jibo/Jibo/Skills/ and /opt/jibo/Skills/
  • Launches @be/be (the Be skill) as the default running skill
  • Builds a combined voice-launch grammar from all skills' launch.rule files and feeds it to the Global Listen service
  • Monitors the ASR stream — when a launch phrase is recognised it terminates the current skill and starts the new one
  • Exposes the browser UI and HTTP API on port 8779 for manual control
✅ Installing custom skills

Drop a skill package into /opt/jibo/Skills/ (remount / as writable first), then restart Be — the SSM will pick it up automatically. The skill needs a valid package.json with a "jibo" section and a launch.rule file to be voice-launchable.
