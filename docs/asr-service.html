Local ASR Service

Jibo's on-board speech recognition runs as a local service called jibo-asr-service. It exposes an HTTP + WebSocket API on port 8088 that the rest of the system — and community tools like Re-Commander and jibo-llm — use to trigger listening sessions and receive transcripts.

ℹ️ Prerequisite for voice tools

Re-Commander and jibo-llm both require this service to be running. The wake word ("Hey Jibo") detection and all speech-to-text features go through it.

Enable via the System Manager (recommended)

The cleanest and most permanent method. Jibo's system manager (jibo-system-manager) is responsible for starting and supervising all platform services — body, audio, TTS, LPS, and so on. The ASR service is already defined in its config at /usr/local/etc/jibo-system-manager.json, but ships with "enabled": false. Flipping that flag to true makes the system manager start and restart ASR automatically on every boot, exactly like every other platform service.

  1. Remount the root filesystem as writable: 
    root@jibo:~# mount -o remount,rw /
  2. Open the system manager config and find the "name": "asr" entry. Change "enabled": false to "enabled": true inside the "default" mode block: 
    root@jibo:~# vi /usr/local/etc/jibo-system-manager.json
    The relevant section looks like this — change the highlighted value: 
    {
    "name": "asr",
    "order": 2,
    "executable": "/usr/local/bin/jibo-asr-service",
    "modes": {
        "default": {
            "arguments": ["-c", "/usr/local/etc/jibo-asr-service.json"],
            "environment": {},
            "directory": "",
            "enabled": true    ← change false to true
        },
        ...
    }
}
  3. Reboot Jibo: 
    root@jibo:~# reboot
  4. After boot, confirm the service is running: 
    root@jibo:~# ss -tlnp | grep 8088
✅ Why this is the right approach

The system manager monitors all managed services and restarts them if they crash — the same crash recovery that covers body, audio, tts, and lps. The ASR service even has its own crash code (SERVICE_CRASH_ASR) already wired up in the config, waiting to be used.

ℹ️ Already on JiboOS?

If you have the JiboOS community update installed, its Be skill includes an ai-bridge.js that detects when port 8088 is closed and spawns the ASR service on demand. If voice features are already working for you, you may already be covered and don't need to make this change. The system manager method above is still preferable because it starts the service earlier (before Be loads) and provides crash recovery — but it is not strictly required if ai-bridge is handling it.

Starting the service manually (one-off)

If you just want to start the service for a single session without making it permanent, SSH in and run: 

root@jibo:~# /usr/local/bin/jibo-asr-service -c /usr/local/etc/jibo-asr-service.json &

What the service provides

EndpointProtocolPurpose
:8088/asr_simple_interface HTTP POST Start / stop a speech recognition task
:8088/audio_source HTTP POST Control the ALSA audio input channel
:8088/asr_control HTTP POST Service handshake and maintenance commands
ws://<ip>:8088/simple_port WebSocket Stream of recognition events (partial + final transcripts, hotphrase, end-of-speech)
ws://<ip>:8088/port WebSocket Full low-level ASR event stream

Example: trigger a listening session

# Start a speech-to-text task (run from your computer, not Jibo)
$ curl -X POST http://<jibo-ip>:8088/asr_simple_interface \
  -H "Content-Type: application/json" \
  -d '{
    "command": "start",
    "task_id": "test1",
    "audio_source_id": "alsa1",
    "hotphrase": "none",
    "speech_to_text": true
  }'

Then connect a WebSocket client to ws://<jibo-ip>:8088/simple_port to receive transcript events.
