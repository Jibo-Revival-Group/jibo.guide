Retarget to a Local Pegasus

Jibo's higher-level voice pipeline runs through a service called Jetstream, which connects to a Pegasus hub — the WebSocket server that originally mediated skill launches, conversation turns, and cloud notifications. By editing one config file on the robot you can point Jetstream at a locally-hosted Pegasus replacement instead.

ℹ️ What Pegasus is

Pegasus was Jibo's real-time communication hub — the bridge between the robot's on-device Jetstream service and the cloud backend. It handled the WebSocket session that delivered parsed voice commands, skill launch signals, and server-side notifications. A local Pegasus replacement can restore that channel on your own network.

The File

Everything is controlled by a single file on the robot:

/usr/local/etc/jibo-jetstream-service.json

Steps on the Robot

  1. SSH into Jibo: 
    root@jibo:~# ssh root@<jibo-ip>
  2. Remount /usr/local as writable — it's read-only by default: 
    root@jibo:~# jibo-mount --rw

  3. Set the three override properties using Python (nano doesn't exist on Jibo). Replace the IP and port with your hub's values: 

    root@jibo:~# python -c "
import json
f = '/usr/local/etc/jibo-jetstream-service.json'
d = json.load(open(f))
d['HubClient']['override'] = {
    'hub_hostname': '192.168.1.133',
    'hub_port': 9000,
    'hub_secure': False
}
open(f, 'w').write(json.dumps(d, indent=4))
"
    ℹ️ Individual property one-liners

    If you only want to change one value at a time:

    python -c "import json; f='/usr/local/etc/jibo-jetstream-service.json'; d=json.load(open(f)); d['HubClient'].setdefault('override',{})['hub_hostname']='192.168.1.133'; open(f,'w').write(json.dumps(d,indent=4))"
python -c "import json; f='/usr/local/etc/jibo-jetstream-service.json'; d=json.load(open(f)); d['HubClient'].setdefault('override',{})['hub_port']=9000; open(f,'w').write(json.dumps(d,indent=4))"
python -c "import json; f='/usr/local/etc/jibo-jetstream-service.json'; d=json.load(open(f)); d['HubClient'].setdefault('override',{})['hub_secure']=False; open(f,'w').write(json.dumps(d,indent=4))"
  4. Restart Jetstream — the system manager respawns it within a few seconds: 
    root@jibo:~# kill -9 $(pgrep -f jibo-jetstream-service)
✅ That's it

Within ~3 seconds a new Jetstream process is up and dialling your hub. You can confirm it connected by checking your hub's logs or watching for a WebSocket handshake from Jibo's IP.

Verifying the Connection

Check that a new Jetstream process is running:

root@jibo:~# ps | grep jibo-jetstream
# should show a fresh PID

Check the service logs to see if it connected:

root@jibo:~# cat /var/log/messages | grep jetstream | tail -20

Reverting

To go back to the default (no override), remove the override block from HubClient and kill Jetstream again. Or rename the key to override_disabled to keep it for later without it taking effect.
