ℹ️ What is this?

Jibo was the world's first social robot. When the original company shut down its servers in 2019, thousands of Jibos performed a final goodbye dance and went silent. The Jibo Revival Group (JRG) is bringing them back through a Tegra K1 boot-ROM recovery vulnerability on hardware we own — we are not hacking anyone else's system.

Choose Your Route

There are currently two ways to modify your Jibo. Both end up in the same place — SSH access and the ability to install community software such as JiboOS releases or BEam.

Recommended

Route A — Automated Installer

Use the community-built jibo_automod tool to handle the eMMC dump, modification, and flash automatically. The current tool supports Linux, macOS, and Windows; Linux remains the simplest path. Requires basic comfort with a terminal.

Route B — Manual

Do every step by hand: build ShofEL2, dump the eMMC, extract the /var partition, edit mode.json, and flash it back. Great for understanding what's happening under the hood.

⚠️ Heads up

The automated route now includes a fast GPT + /var path as well as a full eMMC dump. Both routes still perform low-level writes, so keep a robot-specific backup when possible. If you get stuck, join the Discord — the community keeps current tool guidance there.

What You'll Be Able to Do

  • SSH into your Jibo as root
  • Install community software such as JiboOS releases or BEam
  • Access Jibo's local ASR (speech-to-text) and TTS (text-to-speech) services
  • Build and run custom skills and integrations
  • Use current community tools including Re-Commander, jibo-llm, and the Home Assistant integration
  • Connect to the OpenJibo replacement cloud or run it locally
ℹ️ Terminology and source notes

A Jibo's Tegra fuse state governs its boot/signing identity; it does not make a cloud hostname physically immutable. The archived pvindex fuse documentation distinguishes unfused, developer-fused, and production-fused units. The current recovery and replacement-service status is tracked in the community's AutoMod, OpenJibo, BEam, and BEaker repositories.

FAQ

Is this safe? Could I brick my Jibo?

The initial AutoMod recovery path changes mode.json on the /var partition and writes that partition back. It does not alter the Tegra fuse state or make unsigned boot images valid. We strongly recommend keeping the generated var_partition_backup.bin; a full eMMC dump (Route B or AutoMod --dump-only) also preserves unit-specific calibration data for recovery.

Is Jibo fully back to normal?

The original Jibo cloud is still gone, so there is no single drop-in replacement for every original feature. The community now has working local services, BEam skills, OpenJibo cloud work, Home Assistant, and browser/LLM tools, but compatibility depends on the robot image and the path you choose. Check the linked project repositories and Discord for release-specific status.

Do I need to be a programmer?

Route A (automated) requires only basic comfort with a terminal — running a script and following prompts. Route B requires understanding Linux commands and tools like dd, fdisk, and mount. No coding knowledge is needed for either route.

What Jibo hardware is supported?

All known Jibo units use the same NVIDIA Tegra K1 (T124) SoC and eMMC layout. Both V1 and V2 Jibos should work with this guide. V2 Jibos have the MIT Scratch extension software pre-installed, which is a bonus.

What OS do I need on my computer?

Linux is simplest (any distro with libusb). The current AutoMod launcher also supports macOS with Homebrew and Windows with MSYS2/Zadig. WSL2 remains an option, but USB passthrough needs additional setup.

Is this free?

Yes, completely. As KevinKor from the JRG put it: "I am not charging any money for this. This project isn't a business; it's a labor of love."
