Route B — Step 1: Environment Setup

This is the manual route. You'll do every step by hand — which means you'll understand exactly what's happening and can debug any issues. By the end of these three pages, Jibo will be booted in developer mode with SSH access.

🚨 Read Before Proceeding

By following this guide you acknowledge that all actions are taken entirely at your own risk. The Jibo Revival Group, the authors of jibo.guide, and all community contributors are not responsible or liable for any damage, data loss, or permanent malfunction to your device. This process involves low-level hardware access and direct modification of your robot's firmware storage. If you are unsure about any step, ask for help on the Discord before continuing.

⚠️ About ShofEL2

The maintained community workflow is the Jibo-specific ShofEL2 source bundled in the current JiboAutoMod repository. The standalone T124 repository has an older, generic README; do not substitute an arbitrary ShofEL2 fork or payload. Route A is recommended if you do not specifically need to inspect each manual step.

What You Need

  • A Linux machine (spare laptop, Raspberry Pi, desktop PC — anything with at least 20 GB free storage for a full dump; more is useful for a second backup). CachyOS, Arch, Ubuntu, and Debian are commonly used. The manual commands below are written for Linux; current AutoMod also supports macOS and Windows.
  • A micro-USB cable that you know is a data cable (not charge-only — many phone charger cables are charge-only and will not work)
  • Your Jibo's IP address — look this up before you start and write it down somewhere
  • About 2–4 hours for a full eMMC read, plus time for setup
  • Basic familiarity with the Linux terminal
🚨 Note your Jibo's IP address now

You'll need Jibo's IP to SSH in after the mod. If you forget it, you'll have to redo hours of work. Check your router's device list or Jibo's settings screen (cog → Info → Network) and write it down.

Part 1 — Connect Jibo via USB (RCM Mode)

Jibo's NVIDIA Tegra K1 chipset has a Recovery Mode (RCM) that allows direct USB read/write access to the eMMC storage. We use this to dump and modify the firmware.

The USB port, Reset button, and RCM button are all located behind the circular panel on the back of Jibo's head. Remove or swing open that panel to access them.

Back panel of Jibo's head. The micro-USB port is at the top; Reset and RCM buttons are circled.

  1. Open the panel on the back of Jibo's head to expose the ports. Plug your micro-USB data cable from your Linux machine into the micro-USB port at the top of the panel.
  2. Hold the RCM button (the lower of the two circled buttons — a small plastic button) while pressing the Reset button (the upper button, also small and plastic). Jibo will show a red light on his face ring and will not boot normally. This is correct.
  3. Verify Jibo is in RCM mode on your Linux machine: 
    $ lsusb
    You should see a line like this: 
    Bus 001 Device 007: ID 0955:7740 NVIDIA Corp. APX
    The important part is 0955:7740. If a different NVIDIA/APX identifier appears, stop before writing and use the current AutoMod detection guidance or ask in Discord rather than guessing at a compatible payload.
⚠️ Don't see the APX device?
  • Try a different USB cable — charge-only cables are the #1 cause of this
  • Try a different USB port (avoid USB hubs)
  • Make sure you held the RCM button the whole time while pressing reset
  • Check the Troubleshooting page for more help

Part 2 — Install Dependencies

Install the build tools and libraries ShofEL2 requires:

Arch / CachyOS / Manjaro:

$ sudo pacman -S --needed base-devel libusb git python python-pip \
    arm-none-eabi-gcc arm-none-eabi-newlib

Ubuntu / Debian / Raspberry Pi OS:

$ sudo apt update
$ sudo apt install build-essential libusb-1.0-0-dev git python3 python3-pip \
    gcc-arm-none-eabi libnewlib-arm-none-eabi

Fedora:

$ sudo dnf groupinstall "Development Tools"
$ sudo dnf install libusb1-devel python3-pip
# Also install your distro's arm-none-eabi-gcc and arm-none-eabi-newlib packages.

macOS: the automated launcher is the supported macOS path. Install Xcode Command Line Tools and the Homebrew dependencies, then use Route A:

$ xcode-select --install
$ brew install libusb pkgconf arm-none-eabi-gcc e2fsprogs

Part 3 — Clone and Build ShofEL2

We use the Jibo-specific T124 build of ShofEL2 (the Fusée Gelée exploit adapted for the Tegra K1). The current JiboAutoMod repository carries the source and payloads it actually builds, so compile that copy instead of relying on the obsolete third-party branch referenced by earlier versions of this guide: 

$ cd ~
$ git clone https://github.com/Jibo-Revival-Group/JiboAutoMod.git
$ cd JiboAutoMod
$ make -C Shofel
ℹ️ "Error code 1" from make

If make exits with error code 1, don't panic. Check whether a shofel2_t124 executable was created in Shofel/: 

$ ls -la Shofel/shofel2_t124

If the file exists, the build succeeded. The error is a known quirk of the Makefile's exit handling.

Verify the build:

$ ./Shofel/shofel2_t124 --help

Your environment is ready. In the next step, use ~/JiboAutoMod/Shofel/shofel2_t124 for the ShofEL2 executable (or set SHOFEL_DIR to that directory in your shell). Continue to dump Jibo's eMMC.
