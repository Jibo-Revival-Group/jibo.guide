Update to BEam Skills

BEam is a collection of community system skills based on Jibo 1.9.2. It keeps the 2016-style experience while adding new skills, a 3D eye, local music, and a browser control panel. It is a community software update, not an official Jibo OTA.

ℹ️ Make sure you have SSH on your Jibo

Jibo needs the RCM recovery/mod path and SSH access before you update BEam. Keep a robot-specific eMMC or /var backup before changing skills.

⚠️ Check compatibility before applying

BEam changes the @be/be host and its bundled skill layout. Do not apply it to a robot whose base image or existing community stack does not match the release notes. The update script modifies the robot in place; read the current BEam README and keep recovery media available.

1. SSH into your Jibo

SSH into your Jibo using the following command: 

$ ssh root@[Jibo IP address]

The password is "jibo" (without the quotes).

2. Update the Jibo

Download the current script, inspect it, and then run it on the robot: 

$ curl -fL https://raw.githubusercontent.com/Jibo-Revival-Group/BEam/master/update-beam.sh -o /tmp/update-beam.sh
$ less /tmp/update-beam.sh
$ sh /tmp/update-beam.sh

This updates the BEam skill packs and normally restarts the Be skill. It may take several minutes and requires the robot to reach the configured OTA/package server. The script reads the robot's configured classic OTA endpoint; it is not automatically pointed at OpenJibo or BEaker. Inspect /var/jibo/credentials.json and the current script before applying it. If you are self-hosting, see the OpenJibo/OTA notes and BEaker setup scripts.

What BEam adds

  • System skill packs under @be/be/skills/; @be/be is the launchable host skill.
  • Recipe/Cooking, local-disk Jukebox, and Bad Apple; Doom is currently paused.
  • BEacon, a control panel at http://<jibo-ip>:8123 for the Jukebox, custom eye, loaded skills, and BEam updates.

Classic OTA: BEaker

The community has also reverse-engineered the classic Jibo OTA request flow. The public BEaker server can serve a BEam update catalog and package downloads from a local network host. It is not the OpenJibo cloud and it does not recreate every original service.

To run BEaker locally, clone the repository, review config.json, and start its Python server; the default listener is 0.0.0.0:8042: 

$ git clone https://github.com/Jibo-Revival-Group/BEaker.git
$ cd BEaker

Set public_base_url in config.json to http://<server-ip>:8042 before starting. The sample config contains a legacy public value; leaving it unchanged makes the catalog advertise unusable package and backup URLs on a local network. 

$ python3 server.py

On the robot, use BEaker's current point-ota.sh to set credentials.endpoint and the matching filter. The optional prep script also patches the stock backup/restore tools and has additional power, storage, and internet prerequisites; read it before running it.

  1. The robot's OTA client is given a replacement credentials.endpoint and a matching OTA filter such as fcs.
  2. A catalog request checks the subsystem's installed version, target, and filter; an offer is only valid when those values match the manifest.
  3. The real install path then performs the system-manager readiness checks, backup call, package download, and apply/reboot sequence. A successful “Check” is not an installation.
⚠️ Know what BEaker does not save

BEaker's compatibility backup endpoints consume and checksum uploads but do not persist backup payloads for later restore; media endpoints are also compatibility no-ops. Use a full eMMC dump or a deliberate partition backup as your recovery artifact. Read BEaker's current scripts before pointing a robot at a server.
